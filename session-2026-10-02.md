## ☁️ 1. libSQL Integration Architecture

### The Problem: SQLite C Global Runtime Collision
When using `rusqlite` (with `bundled` feature) alongside `libsql` (with default local features), `libsql-sys` attempts to invoke `sqlite3_config()` to configure process-level threading options. Since SQLite is already initialized by `rusqlite`, SQLite returns error code `21` (`SQLITE_MISUSE`), causing a fatal process panic:
```text
assertion `left == right` failed: libsql was configured with an incorrect threading configuration ...
left: 21, right: 0
```

### The Solution: Decoupled Pure Remote Client
In [`Cargo.toml`](file:///Users/2.o/superconsole/src-tauri/Cargo.toml):
```toml
libsql = { version = "0.9", default-features = false, features = ["remote", "tls"] }
```
- Disables `core`, `replication`, and `libsql-sys` (C FFI).
- Uses libSQL's pure Rust async Hrana/WebSocket/HTTP client.
- Result: **Zero C symbol conflicts**, smaller binary size, and high-performance remote pooling to Turso Cloud CentralDB and UserDB.

### Strongly-Typed Query Execution ([`cloud.rs`](file:///Users/2.o/superconsole/src-tauri/src/cloud.rs))
```rust
pub async fn libsql_connect(cfg: &TursoConfig) -> Result<libsql::Connection, String> {
    let clean_url = cfg
        .url
        .trim()
        .replacen("libsql://", "https://", 1)
        .replacen("wss://", "https://", 1);
    let db = libsql::Builder::new_remote(clean_url, cfg.token.clone())
        .build()
        .await
        .map_err(|e| format!("Failed to build libSQL client: {}", e))?;
    db.connect()
        .map_err(|e| format!("Failed to connect via libSQL: {}", e))
}
```

## 🧠 2. Agent Semantic Vector Memory (`VectorMemoryStore`)

### Architecture
- **Storage**: In-process SQLite `BLOB` storage inside `superconsole.db`.
- **Similarity Metric**: Cosine similarity computed in pure Rust across $n$-dimensional float embeddings:
  $$\text{sim}(\vec{a}, \vec{b}) = \frac{\vec{a} \cdot \vec{b}}{\|\vec{a}\|_2 \|\vec{b}\|_2}$$
  $$\text{distance} = 1.0 - \text{sim}(\vec{a}, \vec{b})$$
  $$\text{score} = \max(0.0, \text{sim}(\vec{a}, \vec{b}))$$
- **Performance**: $<0.5\text{ ms}$ for 1,000 vector comparisons in RAM.

### Schema (`memory_vectors`)
```sql
CREATE TABLE IF NOT EXISTS memory_vectors (
    id           TEXT PRIMARY KEY,
    workspace_id INTEGER NOT NULL DEFAULT 0,
    category     TEXT NOT NULL,
    slug         TEXT NOT NULL,
    title        TEXT NOT NULL,
    summary      TEXT NOT NULL,
    content      TEXT NOT NULL,
    embedding    BLOB NOT NULL,
    created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_mem_vectors_ws ON memory_vectors (workspace_id);
CREATE INDEX IF NOT EXISTS idx_mem_vectors_cat ON memory_vectors (category);
```
