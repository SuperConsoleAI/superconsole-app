# Session — 2026-07-07

## What was broken

**1. Profile switch was eternal (took forever)**
Every time you switched profiles, the app ran 748 SQL `CREATE TABLE` statements against Turso — even for databases that were already set up. The app had no memory of whether a database was provisioned or not.

**2. All profiles showed the same data**
The `switch_project` command was not properly clearing the old UserDB connection. Switching from Alex Hormozi → Iman Gadzhi still showed Alex's data because the old connection was reused.

**3. Full page reload on every switch**
The sidebar was using `window.location.href = "/dashboard"` — meaning every profile or org switch caused a full browser reload, losing all state.

**4. No status page in the Tauri app**
The web app had a `/settings/status` page to provision databases. The Tauri app had no equivalent — no way to know if a profile's database was ready.

**5. Too many Turso requests**
The layout was calling `getUserdbStatus` (a Turso HTTP round-trip) on every single page navigation, not just once.

---

## What we fixed and how it works now

### Provisioning — 748 queries → 0 on repeat

**Central DB `userdb` table now has `last_provisioned_at` column.**

- On profile switch → Rust checks this column first (1 tiny query)
- If `NULL` → run 748 statements to set up the schema, then stamp the timestamp
- If set → skip entirely. Done.

New profiles only provision once, ever. After that: zero schema queries on every switch.

### Profile data isolation — correct data per profile

`switch_project` now explicitly:
1. Drops the current UserDB connection
2. Reads the new profile's credentials
3. Creates a fresh `UserDb` connection to the correct Turso database

Each profile has its own Turso DB. Now each switch correctly points to the right one.

### Status page — `/dashboard/settings/status`

New page in the Tauri app that mirrors the web app's status page.

- If a profile's `last_provisioned_at` is `NULL` → app automatically redirects here
- Shows the profile's Turso URL, provision state, and table list
- "Continue" button → runs provisioning → stamps Central DB → shows "Go to Dashboard"
- "Re-Provision All" button available for already-provisioned databases

Auto-redirect happens on: app boot, profile switch.

### Navigation — SPA (no more full reloads)

All `window.location.href` replaced with Qwik's `nav()`:
- Profile switch → `nav("/dashboard")` or `nav("/dashboard/settings/status")`
- Org switch → `nav("/dashboard")`
- No reload, no lost state

### Request count — two-layer cache

**Layer 1 — Frontend localStorage:**
Key: `bk-provisioned-{profileId}` → stores the `last_provisioned_at` timestamp.
- First switch to a profile → checks Turso once → caches result
- Every subsequent navigation → localStorage hit → zero Turso queries

**Layer 2 — Rust in-memory HashSet (`ready_profiles`):**
After first successful connect to a profile, the profile ID is added to an in-memory set.
- Re-switching to same profile (same session) → skip `last_provisioned_at` query + seed check entirely → just reconnect the TCP socket
- Zero Central DB + Zero UserDB guard queries

### Keychain-miss path — for fresh installs

When the OS keychain has no credentials for a profile (new install, new machine):

1. `load_from_keychain` returns `Err`
2. `get_userdb_creds_full` fetches `turso_url` + `encrypted_token` from Central DB
3. `vault::decrypt` decrypts using `ENCRYPTION_SECRET:profile_id` (AES-256-GCM, PBKDF2, same scheme as web app)
4. `store_in_keychain` saves plaintext URL + token to OS keychain
5. `UserDb::connect` connects
6. Future switches → keychain hit, no decrypt needed

**Tested:** deleted both `turso_url_` and `turso_token_` for Iman Gadzhi → switched → data loaded → app re-saved both entries to keychain (`crtr=aapl` confirmed).

## Full flow: what happens when you switch profiles

```
User clicks profile in sidebar
         │
         ▼
switchProject(profileId)     [Tauri IPC]
         │
         ├─ ready_profiles cache hit? ──YES──► UserDb::connect(keychain creds)
         │                                              │
         │                                             done (0 extra HTTP calls)
         │
         └─ NO (first switch this session)
                   │
                   ├─ keychain has creds?
                   │         │
                   │        YES ──► get_last_provisioned_at (1 Central DB query)
                   │         │
                   │        NO  ──► get_userdb_creds_full (1 Central DB query)
                   │                    └──► vault::decrypt
                   │                    └──► store_in_keychain
                   │
                   ├─ last_provisioned_at NULL?
                   │    YES ──► provision_user_database (748 stmts, one-time only)
                   │            └──► mark_provisioned in Central DB
                   │
                   ├─ profile row in UserDB?
                   │    NO ──► seed from Central DB (INSERT OR IGNORE)
                   │
                   └──► mark in ready_profiles
                        └──► UserDb::connect


Frontend (sidebar JS after switchProject)
         │
         ├─ localStorage["bk-provisioned-{id}"] exists?
         │    YES ──► nav("/dashboard")   ← zero Turso queries
         │
         └─ NO ──► getUserdbStatus() ──► check last_provisioned_at
                       │
                       ├─ NULL ──► nav("/dashboard/settings/status")
                       │              user clicks Continue → provision → stamp → dashboard
                       │
                       └─ SET ──► cache in localStorage → nav("/dashboard")
```
